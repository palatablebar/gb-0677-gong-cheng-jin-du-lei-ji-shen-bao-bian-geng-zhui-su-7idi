# 计量定义

claim_id唯一；item为清单编码，支持钢筋与001等别名。period为YYYY-MM。累计数量按t或m³保存，当前周期工程量=本次累计-前期已审累计。previous_revisions参数可指定更正后的前审数量，重新计算形成不同批次，不覆盖旧证据。

C0原始价100元，C1自2026-11生效为120元，DRAFT未批准不可结算。负进度必须reversal=approved作为已批冲回标记。扣留质保金5%、预付款扣回10%分别按分量化，净额=本期总额-质保金-预付款扣回，负进度同步冲回扣留。reported为原申报净额，差异=复算净额-reported。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 补充变更的适用边界

补充变更（supplement）只重述单价和生效起点，用 `supplement_to`（或 `parent`/`base_change`）指向原变更。它不另起新链，而是挂在原变更的**变更链**上。

| 条款 | 补充变更重述 | 补充变更未重述 |
|---|---|---|
| 单价 | 以补充变更为准 | 不允许，必须重述（`MISSING_PRICE`） |
| 生效起点 | 以补充变更为准 | 沿用原变更起点 |
| 数量上限 cap | 以补充变更为准 | 向原变更继承，`cap_source` 指向原变更 |
| 冲回规则 reversal | 以补充变更为准 | 向原变更继承，`reversal_rule_source` 指向原变更 |
| 适用清单 items | 以补充变更为准 | 向原变更继承 |
| 区间终止 end | 以补充变更为准 | 向原变更继承 |

生效区间统一 `[effective,end)`，`end` 为空表示不限。每笔申报按 period 在本链已批版本中选择**生效起点最晚且覆盖该周期**的版本：补充变更自其生效月份起接管，此前周期仍按原变更单价计价。因此：

- 整份替代签证不会把历史周期改按补充单价重算；
- 补充变更独立成新单的风险被消除：上限与已用额度都记在原链上，前期额度不会被重置；
- 全部回退按旧单价计价只发生在补充变更生效之前的周期，属于正确结果。

同一生效起点出现多个补充变更返回 `CHANGE_AMBIGUOUS`；引用成环返回 `CHANGE_CYCLE`；引用的原变更不存在返回 `UNKNOWN_REFERENCE`。审批状态不属于可继承条款：补充变更必须自行标注 `approved`（或 `status=approved`），否则按未批准隔离为 `UNAPPROVED_CHANGE`。申报行未引用补充变更时，历史周期仍按原变更执行。

继承条款在结果中以中文标签输出（`inherited_text`，如“数量上限、适用清单、冲回规则”），`inherited_terms` 保留英文字段名供机读。

额度按 (变更链, 清单) 归集：已用 = 该链最新周期的已采纳累计量；剩余 = 上限 − 已用；剩余金额 = 剩余 × 现行单价。累计量超过上限的申报整行隔离为 `CAP_EXCEEDED`，不进入本期计量。已批冲回会下调累计量，相应恢复可用额度。

每行申报写入 `claimed_change`（申报所引版本）、`applied_change`（实际适用版本）、`change_chain`、`effective_interval`、`inherited_terms`、`cap_source`、`reversal_rule_source` 与 `change_basis`，使各笔申报都能追到原依据。

## 本期计量结果与发布

工作台按变更链归并为唯一可签认结果，给出 `current_change`（现行变更）、`inherited_terms`（继承条款）、`effective_interval`（生效区间）与 `unsigned_remaining`（未签认余量：剩余数量、剩余金额、已用量、上限、待签认金额）。`result_id` 由结果内容摘要生成，同源重算保持稳定。

`POST /api/runs/<id>/publish` 原子发布：

- 同一 `result_id` 只在首次写入，重试返回原记录（`created=false`），不重复计量；
- 发布失败（400/404/409）不改动任何既有记录，旧版继续可用；
- 同一 `result_id` 内容变化视为改写已发布结果，返回 409 `PUBLISH_CONFLICT`，不删除不覆盖；
- 发布只新增 `publications` 记录，从不改写批次和原始申报行，因此不存在“原申报被覆盖后无法恢复”。

签认 `POST /api/publications/<result_id>/sign` 需要版本号；已签认结果再次提交返回 409 `ALREADY_SIGNED`，陈旧版本返回 409 `STALE_VERSION`。重复发布不会把已签认结果重置为待复核。
